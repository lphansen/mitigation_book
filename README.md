# mitigation_book

This repo contains the source code and generated HTML for:

```text
https://lphansen.github.io/mitigation_book/intro.html
```

## Branch Structure

Use two branches:

```text
main      source code plus generated docs/_build/html
gh-pages  production HTML served by GitHub Pages
```

Work on `main`. Build into `docs/_build/html`. Publish by copying `docs/_build/html/` into the root of the `gh-pages` worktree.

## Build Environment

This site uses the old Jupyter Book/Sphinx build stack. Use `jupyter-book 0.x`, not `1.x` or `2.x`.

Create the environment once:

```bash
conda create -n jb015 python=3.10 -y
conda activate jb015
python -m pip install -r docs/requirements.txt
```

## Paper Source For The Tables

The markdown tables under `docs/_static/table/` are generated from the paper
tex by `tools/sync_tables_from_tex.py`. The script reads
`paper/mitigation_main.tex` and `paper/mitigation_appendix.tex`, where `paper/`
is a gitignored symlink (or copy) of the Overleaf clone:

```bash
ln -s ../mitigation_paper paper
python tools/sync_tables_from_tex.py          # rewrite the tables
python tools/sync_tables_from_tex.py --check  # report stale tables only
```

`build.sh` runs the sync automatically when `paper/` is present and otherwise
uses the committed tables.

The interactive value function derivative surfaces in chapter 1
(`docs/_static/df_V_m{2,3}_surface_xik*.html`) are drawn by
`tools/plot_value_surfaces.py` from the Fine grid tech-only HJB solutions of the
replication repository. The script imports the grid builder and the
finite-difference routine from that repository (`python/src/`), so it needs a
clone of it and its shared environment:

```bash
source /project/lhansen/mitigation.sh
python tools/plot_value_surfaces.py --repo ~/two-capital-climate-change \
    --solution-dir <tech_only double_resolution dataset>
```

The paper figures under `docs/_static/paper/` are
copies of `results_in_paper/Figure*.png` from the paper repository, resized to
2000 px width.

## How To Modify

Edit source files under `docs/`.

Use:

```text
docs/intro.md              edit the landing page
docs/_toc.yml              add, remove, or reorder chapters
docs/_config.yml           change book settings and build options
docs/notebooks/            edit chapter notebooks
docs/_static/              add figures, CSS, and interactive HTML
docs/climate.bib           edit bibliography entries
docs/references.bib        edit bibliography entries
```

Do not edit `docs/_build/html/` directly. It is generated by `bash build.sh` and will be overwritten.

## Notebook Execution

Notebook execution is currently off in `docs/_config.yml`:

```yaml
execute:
  execute_notebooks: 'off'
```

Keep it off unless the missing simulation scripts and data are restored. Some notebooks refer to external scripts such as `./conduction/...`, which are not currently in this repo.

## Publish To GitHub Pages

The live site is served from the `gh-pages` branch. When working from
`rebuildjul26`, publish the generated website by copying `docs/_build/html/`
into a separate `gh-pages` worktree.

Run this from the repo root:

```bash
conda activate jb015
bash build.sh
```

Create a separate worktree for the `gh-pages` branch the first time you publish:

```bash
git worktree add -b gh-pages ../mitigation_book-gh-pages origin/gh-pages
```

On later publishes, reuse the existing worktree instead of creating it again:

```bash
cd ../mitigation_book-gh-pages
git pull origin gh-pages
cd ../mitigation_book
```

Copy the built HTML into that worktree:

```bash
rsync -a --delete docs/_build/html/ ../mitigation_book-gh-pages/
```

Commit and push the published site:

```bash
cd ../mitigation_book-gh-pages
git status
git add -A
git commit -m "Update site from rebuildjul26"
git push origin gh-pages
```

Check the live site:

```text
https://lphansen.github.io/mitigation_book/intro.html
```

## Common Issues

If `build.sh` reports `jupyter-book 1.x` or `2.x`, activate the legacy environment:

```bash
conda activate jb015
```

If the sidebar is missing pages, update `docs/_toc.yml`.

If a static asset is missing, put it in `docs/_static/` and reference it as `_static/...`.
